# Supervised vs unsupervised learning
Supervised learning learns a mapping X→y from labeled data (regression for continuous outputs, classification for discrete ones). Unsupervised learning finds structure in unlabeled data — clustering, dimensionality reduction, density estimation.
- Example 1: IMU→joint-angle regression — X = accelerometer/gyro streams, y = joint rotations, labeled against mocap ground truth. Supervised.
- Example 2: PCA over a corpus of face scans to find a low-dimensional expression manifold, with no semantic labels involved — this is literally how a lot of blendshape rigs get built. Unsupervised.
- Likely follow-up: "What if you only have a little labeled data?" → self-supervised pretraining (e.g. wav2vec2/HuBERT predicting a masked audio frame) followed by supervised fine-tuning on the small labeled audio→viseme set — the standard recipe when labeled lipsync data is scarce.
  - Viseme = the visual counterpart of a phoneme, i.e. the mouth/lip shape made while producing a sound — many-to-one with phonemes (/p/,/b/,/m/ all look like closed lips), typically ~10-20 classes (e.g. Disney's 12-viseme set). "Viseme data" = audio paired with ground-truth mouth shape per frame, either discrete viseme class labels or continuous blendshape/mesh coefficients (the latter is what most production facial animation uses, since it captures coarticulation/intensity). Collected via synced audio+mocap (manual annotation or blendshape weights auto-extracted from a fitted 3D rig) or cheaper forced-alignment phoneme timelines pushed through a phoneme→viseme lookup table — the mocap/annotation requirement is exactly why labeled viseme data is scarce.
  - How the two-phase recipe actually works: "self-supervised" isn't unsupervised — it's supervised-style training (input, label, loss) but the label is manufactured from the unlabeled data itself, no human needed. Concretely: mask a chunk of raw audio, ask the network to predict what was there — the ground truth is just the original, un-masked audio, free. To solve that task well the network is forced to learn phoneme structure, coarticulation, prosody, speaker/noise variation — producing a general-purpose audio encoder trained on huge, cheap, unlabeled speech corpora (thousands of hours). Phase 2 bolts a small head onto that pretrained encoder and trains only the head (or lightly fine-tunes the whole thing) on the small human-labeled audio→viseme set — the model isn't relearning "what is speech" anymore, just the narrow mapping "these features → this mouth shape," which is why a few hours of labeled data is enough. Analogy: phase 1 = becoming fluent in English by guessing blanked-out words in a huge pile of text (the text corrects you, no teacher needed); phase 2 = one afternoon learning medical-transcription vocabulary on top of that fluency. In practice phase 1 is already done for you — you download the wav2vec2/HuBERT checkpoint — and phase 2 is the part you actually run.
  - wav2vec2: CNN encodes raw waveform → mask latent spans → Transformer contextualizes → contrastive loss picks the true quantized latent among distractors at masked positions.
  - HuBERT: masks + cross-entropy against k-means pseudo-labels (cluster MFCCs first pass, then the model's own hidden states over ~2 iterations) — more stable to train than wav2vec2's contrastive loss, the more common backbone today.
  - Why it transfers to visemes: SUPERB-benchmark findings show mid-layers of these models encode phonetic content most strongly (lower layers ≈ raw acoustics, upper layers drift toward speaker/task-specific info) — exactly the representation visemes need, since visemes are driven by phoneme identity.
  - Fine-tuning recipe: freeze the CNN feature extractor, fine-tune the Transformer with layer-wise LR decay (or freeze it too and train just a small head), frame-wise regressor/GRU head → viseme/blendshape coefficients, MSE or cross-entropy loss. Watch the frame-rate mismatch (audio encoder ~50Hz vs facial capture 30/60fps) — needs interpolation/upsampling.
  - Ties to bias-variance below: this is the fix for the high-variance failure mode (big Transformer memorizing one actor's quirks) — pretraining absorbs most of the model's capacity from the unlabeled corpus, so the scarce labeled set only has to teach the final mapping.

# Bias-variance tradeoff
Bias is error from overly simplistic assumptions (underfitting); variance is error from sensitivity to the particular training sample (overfitting). Expected test error ≈ bias² + variance + irreducible noise. More model capacity trades bias down for variance up.           - Example 1: A linear model mappo joint angle, ignoring nonlinear sensor drift — underfits, high error on both train and val. High bias.
- Example 2: A large Transformer for audio→blendshape regression trained on one actor's small dataset — memorizes that actor's coarticulation quirks, fails on a new speaker at test time. High variance.
- Likely follow-up: "Does more data fix this?" → more data (specifically more identities/speakers) fixes variance; a more expressive model is what fixes bias.

# Overfitting
The model fits the training data (including its noise) rather than the underlying pattern, so train loss keeps falling while vd rises. Fixes: more data, L1/L2regularization, dropout, early stopping, data augmentation, simpler model, cross-validation.
- Example 1: L2 regularization oo it doesn't memorize onesubject's motion idiosyncrasies.
- Example 2: Data augmentation via pitch-shift/background-noise/speed perturbation for audio, or sensor-noise injection for IMU data — critical since real-world facial animation has to survive noisy microphones.
- Likely follow-up: "How do you cross-validate here?" → leave-one-subject/speaker-out CV, not random split — random split leakty across train/val and gives afalsely optimistic score. Worth naming unprompted; it's a genuine, non-obvious gotcha in this domain.
