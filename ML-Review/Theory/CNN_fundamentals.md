# CNN fundamentals
A CNN applies small learned kernels convolved across the input instead of fully connecting every pixel to every neuron. Two priors give it its parameter efficiency: locality (a kernel only looks at a small spatial neighborhood at a time) and weight sharing (the same kernel slides across every position, so one set of weights detects a pattern anywhere in the image — this is what gives translation equivariance: shift the input, the feature map shifts the same way, no separate weights needed per position). Stacking conv → nonlinearity → pooling builds a feature hierarchy: early layers learn edges/textures, deeper layers combine these into parts, then whole objects/shapes. Pooling (max/average) downsamples the spatial map — cheaper compute, some translation invariance, at the cost of spatial precision.
- Example 1: Facial landmark/keypoint detection via heatmap regression — a CNN backbone outputs one heatmap per landmark, the predicted (x,y) is the heatmap's peak. Convolutional weight sharing is what makes dense, per-pixel prediction tractable at all; a flattened MLP at the same resolution would need a separate weight per pixel-per-landmark pair, and would need to see every landmark position during training to generalize.
  - The target isn't a coordinate, it's an image: for each landmark, the training label is a 2D Gaussian blob centered on the ground-truth (x,y), mostly zeros elsewhere. A face with 68 landmarks trains against a stack of 68 such heatmaps, not a 68×2 vector — this makes the task image-to-image, a natural fit for a CNN's spatial structure.
  - Architecture shape: encoder-decoder (stacked hourglass/HRNet). Encoder = conv+pooling repeatedly downsamples while growing channel depth — each downsampling stage roughly doubles the effective receptive field for the same kernel size, which is how the network cheaply builds global context (where's the face, roughly where's the mouth) without needing huge kernels or full-res compute throughout. Decoder = upsamples (transposed conv, or upsample+conv) back to full resolution so there's one output value per pixel again. Skip connections carry the encoder's feature map from each matching resolution over to the decoder, reinjecting the fine spatial detail pooling would otherwise destroy — upsampling alone can only interpolate, it can't reconstruct detail that's already gone.
  - Training loss: plain per-pixel MSE (or a focal-loss variant) between predicted and target heatmap, summed over all landmark channels — no exotic loss needed, just "does your blob line up with mine."
  - Inference: take the argmax (peak) of each predicted heatmap, then multiply by the network's stride to map back to image coordinates (the heatmap is usually at lower resolution, e.g. 1/4, than the input). For sub-pixel precision, use a soft-argmax (intensity-weighted average of coordinates around the peak) instead of a hard argmax, which is limited to integer pixel locations at that resolution.
  - Why heatmaps beat direct coordinate regression (CNN → flatten → FC → (x,y)): the heatmap target is smooth and spatially local, a much easier optimization landscape than a single exact-coordinate target with no useful local gradient. It also handles ambiguity gracefully — an occluded landmark can produce a diffuse or multi-peaked heatmap instead of forcing the network to commit to one confident wrong point. Empirically heatmap regression beats direct regression by a wide margin in the pose-estimation/landmark literature.
  - "Stacked" hourglass = chaining several encoder-decoder passes back to back, applying the heatmap loss after each one (intermediate supervision) so each stage refines the previous stage's prediction.
- Example 2: Audio-driven facial animation pipelines that feed mel-spectrograms often route them through a small CNN first (before an RNN/Transformer) — treating the spectrogram as an "image" over (time, frequency) lets convolution pick up local time-frequency patterns (formants, transients) with the same weight-sharing benefit as in vision.
- Likely follow-up: "Why not just flatten the image into an MLP?" → no locality or weight-sharing prior, so it needs a separate weight for every pixel-to-neuron connection — vastly more parameters, more data, and no equivariance (a face seen in a new position isn't recognized by weights that only ever saw it centered).
  - Related gotcha specific to face-tracking: aggressive pooling helps classification (you only need "is this a cat," not *where*), but hurts anything needing precise spatial localization — like landmark/heatmap regression. That's why architectures actually used for this task (stacked hourglass, HRNet) keep a high-resolution branch alive throughout via skip connections, instead of pooling all the way down like a classification backbone would. Worth naming unprompted — a real gotcha, not generic CNN trivia.
